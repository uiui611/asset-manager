# Asset Atelier — Kubernetes / RustFS

プライベートLAN内の個人用ゲーム素材管理アプリ。ログイン画面は設けず、既存NginxのHTTPS経由で利用します。

ソースとKubernetesマニフェストの正本は [uiui611/asset-manager](https://github.com/uiui611/asset-manager) です。`main` への push で GitHub Actions が UI・Rust の検証、コンテナのビルド、GHCR への公開、OIDC 認証付き更新 webhook の通知を行います。通知失敗は許容し、更新完了を待ちません。

## 構成

Lit + TypeScript の画面と最小限のRust API（Axum）を単一コンテナで配信します。ファイル本体はRustFSの既存 `assets` バケット、メタデータはYugabyteDBの専用 `asset_manager` データベースへ保存します。

一覧・タグ・サムネイル・実行中の操作はブラウザのメモリだけに保持し、IndexedDBは使用しません。起動時と一覧更新時にAPIから取得し、保存結果を画面へ反映します。旧ブラウザDBは開かず、そのまま残します。

- 画像・音声・JSONを同じ一覧・同じ保存領域で扱い、登録時の拡張子から「画像」「音声」「JSON」を自動付与します。
- マップ・キャラクター合成・効果音設定もJSON素材です。「マップ編集」「キャラクター合成」「効果音編集」タグで対応エディターを識別します。
- キャラクター合成PNGと効果音WAVは通常の画像・音声素材です。
- 素材の親子関係や派生素材という区別はありません。専用の「タイル分割」ボタンで、分割PNGだけを保存できます。
- 参照先画像が削除されてもJSONの編集・保存を継続できます。欠落箇所はプレースホルダーで表示し、差し替え・解除できます。
- 画像・音声・JSONを既存カード上へドラッグ＆ドロップして追加できます。名前・タグ・説明で検索できます。
- 素材の詳細・一括タグ追加は入力可能なComboBoxを使用します。既定タグとユーザー定義タグを候補から選択でき、新しい名前を入力してEnter（または「作成して追加」）でタグを作成できます。選択済みタグは個別に外せます。画像・音声・JSONの形式タグは自動設定されます。タグ名は100バイト、素材ごとに最大50個まで。ライブラリと画像パレットのタグ絞り込みも入力で候補を検索できます。
- 新規作成は名前なしで開始し、保存時に名前を入力します。「別名で保存する」で独立したJSONを作成できます。
- 編集状態とUndo・Redoはメモリ内だけに保持します。画面移動・新規作成時に未保存の変更を確認し、開く一覧にはサーバー保存済みのJSONだけを表示します。
- 素材登録は「素材を追加」またはドラッグ＆ドロップから確認画面なしで最大2件を並列に実行し、同じ画面で操作を続けられます。画面を移動すると処理を取り消します。音声と効果音JSONは再生ボタン付きリストで表示します。
- 画像パレットはサムネイル・検索・タグフィルタ・名前順／更新順ソート付き。キャラクターはベース画像の大きさにキャンバスと表示倍率を合わせ、矢印キーで移動、Shiftで10px、＋／−で拡大縮小できます。縦横比の維持は既定で有効です。
- キャラクターの選択レイヤーはキャンバス上のドラッグで移動でき、ホイールで表示倍率を調整できます。
- 「元素材を切り出して上書き」は各レイヤーをキャンバスサイズのPNGへ変換し、同じ素材IDで上書きします。位置・倍率・回転・透明度を画像へ反映し、JSONの座標0,0・倍率1・回転0・透明度100%に正規化して保存します。非表示状態は維持。同じ素材の重複参照・欠落は事前エラーです。他のJSONにも元素材の変更が反映され、以前の画像とUndo履歴は戻せません。
- キャラクターJSONは保存時のサムネイルを含みます。元画像の変更や削除による自動再生成はしません。
- 効果音は最大8トラック。開始位置・音量・ミュートを調整してミックスし、各トラックの波形を変更後に更新します。JSONとWAVで保存できます。
- タイル合成は素材ライブラリとスプライトシート再生から利用できます。同じサイズの保存済み画像を選択順・指定列数でPNGにまとめ、サイズ不一致はエラーにします。元画像の削除は任意で、合成保存が成功した後に実行します。
- マップはレイヤーごとにタイル画像セットとコマサイズを指定し、画像内のコマを選んで描画します。
- 複数保存は最大2件、削除・一括タグ更新は最大4件を並列処理し、進捗を表示します。失敗を通知し、未完了分の再試行はユーザーの明示操作で行います。操作記録はメモリ内だけに保持し、次回起動時には復旧・再実行しません。
- ファイル送信を自動再試行しません。画面移動・ページ離脱時は実行中の要求を中断し、未送信分や後続の保存を開始しません。再読込・タブを閉じる際の確認通知では保存や再送を行いません。すでにサーバーが受理した書き込みの取り消しは保証しません。
- 複数素材の更新中に失敗・中断した場合、編集JSONを自動保存しません。完了済みの素材更新は残り、同じ画面に残る編集状態から明示的に保存・再試行します。
- Web Audio対応時は、プリセット・波形・音声パラメータの変更後、操作が250ms止まるとミックス音を自動試聴します。試聴ボタンでも再生でき、停止ボタンは再生と予約済みの自動試聴を取り消します。画面離脱・新規作成・読込時も取り消します。名前編集や初期表示だけでは再生しません。Web Audio非対応時は試聴できませんが、波形更新・JSON編集・WAV出力は利用できます。WAV保存はエクスポートの右側にあります。
- スプライトシート再生で、登録画像または端末から読み込んだ画像を均等格子に区切って確認できます。コマサイズ・余白・間隔・FPS・再生範囲・ループ・コマ送り・表示倍率を指定できます。端末からの画像インポートはサーバーへ登録しません。
- エディターの「開く」はサーバー保存済みJSON、「インポート」はローカルJSONの読込、「エクスポート」はローカルへのJSONダウンロードです。
- 削除は本体の削除で、ゴミ箱機能ではありません。

## 開発・検証

整形は Oxfmt のデフォルト設定を使います。`bun run format` で整形し、`bun run format:check` で確認します。Biome は lint と import 整理に使用します。

```powershell
bun install --frozen-lockfile
bun run schemas
bun run dev
bun run check:ci
bun run test
bun run build
bunx playwright install chromium firefox webkit
bun run test:e2e
cargo test --manifest-path backend/Cargo.toml --locked
```

Vite `/api` はローカルRustサーバー（8080）へ転送します。Rustの環境変数は `deploy/asset-manager.yaml` を参照してください。秘密値は環境変数またはKubernetes Secretで渡し、コミットしません。本番は `https://ubuntu.home.arpa/asset-manager/` を使用します。

`docker build -t asset-manager:local .` で、クリーンなチェックアウトから UI と Rust をまとめてビルドできます。事前の `dist` 作成は不要です。Bun 1.4.2、Rust 1.98.1、各 lockfile を使用します。

Deployment は `ghcr.io/uiui611/asset-manager:main` と `imagePullPolicy: Always` を利用します。webhook 受信側は登録済み Deployment の Pod テンプレートを更新します。YAML 自体の変更は [適用手順](deploy/README.md) で別途反映してください。既存 DB・Secret・S3 バケットを引き継ぐため、通常の更新で初期化スクリプトを再実行しません。

Google Drive版の文書は旧版の参考資料です。旧Google Drive上のファイルを削除・自動移行しません。旧IndexedDBの下書き・キャッシュ・操作記録も読み込み・移行・消去しません。既存RustFSバケット内のアプリ未登録オブジェクトも自動登録・削除しません。
