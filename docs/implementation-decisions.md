# 実装時の判断

## ZIP出力を初期版から除外

設計書13.3・26.2に従い、全対象ブラウザで継続的なメモリ使用を保証できる保存経路が確認できるまでZIP機能を提供しない。ZIP全体をBlobへ集積するフォールバックは実装していない。

- ZIPエンコード自体をStreamsで扱えても、ダウンロード先へストリームを書き続ける仕組みが別に必要。
- `showSaveFilePicker()` は広く共通のブラウザ前提ではなく、これだけへの依存は仕様を満たさない。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker)
- Service Worker経由のダウンロードはライフサイクル・中断・タブ終了とブラウザ実装差の検証が必要。初期版で保守可能な全ブラウザ保存経路を確立できていない。
- 単一素材のBlobダウンロードのみ提供。ZIPや全選択素材をメモリに集積するコードはない。

これはZIPの実現不可能性を断定するものではない。将来実装する場合は、エンコード／保存の両方で中断、メモリ上限、Chrome・Firefox・Safariの試験を満たす必要がある。

## 差分同期の開始カーソル

設計書10.2の「初期同期後にカーソル取得」は、初期一覧の取得中に起きた更新を取りこぼす可能性がある。実装では初期一覧取得**前**のカーソルを保持し、全ページ反映後に差分を適用する。最終的なキャッシュとカーソルは同一IndexedDBトランザクションで更新する。無効なカーソルは全件同期へフォールバックする。

## CSPとJSON Schema

Ajvの実行時コンパイルは`Function`を生成するため、`unsafe-eval`を許可しないCSPで動作しない。[Ajvのstandalone機能](https://ajv.js.org/standalone.html)を使ってビルド前に検証コードを生成する。`definitions.ts`がスキーマの正本で、`generated.js`は再生成可能。Unicode文字数検査はコードポイント単位。

## 仮想スクロール

固定高さカードを行単位で仮想化し、表示領域の前後だけをDOMへ出す。可変高さ・ドラッグ並べ替えなどを必要としない初期版では専用ライブラリを追加しない。サムネイルの同時取得は4件に制限する。画像はPNGへ縮小してIndexedDBに保存し、DriveのthumbnailLinkに依存しない。

## 効果音

独自の簡易オシレーターではjsfxr互換にならないため、jsfxr 1.4.1を追加した。波形・エンベロープ・フィルター等は同ライブラリで生成し、PCMのみをWeb Audioに送る。互換JSONは`oldParams: true`のパラメータ形式とし、アプリ用プロジェクトJSONと生jsfxr JSONを別に書き出せる。

## ファイルの競合と再実行

Driveのversionを保存前に確認する。比較と更新の間まで排他的にロックできるわけではなく、単一ユーザー前提の競合検出である。複数ファイル操作はジャーナルを永続化し、amIdを重複防止キーに使う。完了済みのタグ更新やゴミ箱移動も再実行時に確認する。通信が曖昧な作成リクエストをその場で盲目的に再送しない。

## 手動検証が残る項目

今回のWindows Playwright WebKitでは、1万件のIndexedDBへの書き込み準備が90秒を超えた。100件ずつの切り分けでも遅延を確認したため、1万件の一覧テストはメモリ上に用意したデータによるDOM件数・検索検証とし、キャッシュへの大量書き込み性能の達成とは扱わない。Chromium/FirefoxではIndexedDBに1万件を投入する試験も完了している。WebKitの大量書き込み性能は実Safariで再評価が必要。

WebKitの一部環境ではIndexedDBがFile/Blobを保存できないため、同じペイロードをArrayBufferへ変換して再試行する。これはバイナリ内容を変更しない互換対応で、操作の中断・再開に利用する。

- 実GoogleアカウントでのOAuth認可、フォルダ生成、素材登録とDrive UIからの変更。
- Driveの実クォータ、トークン期限切れ、数百MB〜1GB規模のアップロード回復。
- 実Safari/macOSのWeb Audioとインポート音声コーデック。
- 実素材10,000件の同期所要時間、スクロールfps、端末別メモリ。自動テストの合成データ検証と区別する。
